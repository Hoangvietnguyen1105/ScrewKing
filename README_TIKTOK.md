# Screw King — TikTok international

Separate port of ScrewKingUnity. SDK integration now uses the original GameFrameworkMini MoodBoost service layer; the desktop reference project is unchanged.

## Base integration

Copied unchanged: Assets/_Dev/Sdk (255 files), TTSDK 1.1.6-Release (104 files), UniTask (337 files). VContainer is pinned to the base commit 5401e5a7ebc4980a2b82141ffc26391a6547edd7. Tools/verify_sdk_base.py checks file hashes against the supplied template.

TikTokPlatform uses MoodBoostSdk.GetOrCreate and its original initialization, ad service/policy, ad tracking bridge, tracking provider, remote config defaults, lifecycle and haptics. The game adapter supplies level identity, gameplay events and callbacks. ScrewKingLevelTelemetry uses the original LevelTracking and player session service for level_start/end/exit/reopen, elapsed time, retries, revive and booster sequence. Tutorial and startup funnel use the base typed tracking extensions.

Rewarded ads grant a reward only for Completed; skipped/failed/blocked results grant nothing. Interstitials use the base level/cooldown gates. Editor Play uses the base fake ad provider; device builds do not enable fake ads. Browser preview temporarily disables MB_TIKTOK and uses the base null providers, then restores project defines. The MB_TIKTOK player branch was compiled separately.

Assets/Plugins/WebGL/ScrewKingSource.jslib is generated by Tools/build_source_webgl.py from the original rules/Box2D resources, without runtime eval/new Function. Tools/test_source_webgl.cjs verifies 89 levels x 2 seeds, 180 physics steps, transport, error handling, context isolation and disposal.

## Configuration

- MoodBoost > SDK Settings opens Assets/SDKSetting/SdkSettings.asset. Configure Screw King's own mediation/ad-unit IDs here, using the same settings structure as the base. The scene already references this asset. IDs remain empty; template game IDs were not reused.
- Set the public App ID in TTSDK's TikTokGame/Build Minigame window. The Screw King packaging preflight also reads AppId from Resources/TikTok/Settings.asset, created with Create > Screw King > TikTok Settings; set the same public App ID there. No client secret belongs in the client.
- Use WebGL and MB_TIKTOK for the actual TikTok build. Screw King > TikTok > Build TikTok Package validates configuration and opens the vendor packaging window; it does not automatically build/upload a package.
- Browser previews use Screw King > TikTok > Build Optimized Browser Preview. Start Tools/serve_preview.py from this project for http://127.0.0.1:8769 . Output and evidence live in the parent Builds/TikTok directory.
